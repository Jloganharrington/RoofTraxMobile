PHASE B — COC record and extraction
Schema: a completion_certificates table — company_id, pin_id, contract_id, status (draft | signed | voided), document_object_path, document_sha256, signed_by_user_id, signed_at, signer_title, and a line_items jsonb snapshot.

The snapshot holds both sections as extracted: base contract items and PWI items, each with description, optional quantity/unit, and amount in integer cents. Once a COC is signed, the snapshot is immutable — a correction voids and reissues, exactly like contracts.

Extraction: AI pass over the stored approved estimate producing the two sections, following the existing pattern in ahjWizardExtraction.ts and the report compile. It must return line items with amounts in cents and must not invent items — anything it can't attribute to the estimate is omitted and reported, not guessed.

Extraction produces a draft. Amounts are editable by the signer before signing; edits overwrite the snapshot while status is draft.

Also add: change_orders.carrier_reimbursable boolean, default false, set explicitly. Only approved, non-voided, carrier-reimbursable change orders appear on the COC, as their own section between base and PWI. Do not reuse requiredToCompleteScope — it means something else.

Verify: run extraction against the Glass estimate if you can obtain it, otherwise a representative carrier estimate. Paste the extracted sections and reconcile the subtotals against the source document line by line. Report every item the extractor dropped.

Integration checks: pin_profitability unaffected — the COC reads contract and change-order data, it never writes to it. Prove revised_contract_cents is unchanged before and after a COC draft. Full suite.
