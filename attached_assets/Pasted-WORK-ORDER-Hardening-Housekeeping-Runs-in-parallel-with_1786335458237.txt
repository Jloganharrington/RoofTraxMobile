STEP 3 — Transport hardening
Four pre-launch items from the audit. All middleware and transport — none of it touches route authorization.

3a. CORS. app.ts:30 is cors({ credentials: true, origin: true }), which reflects any origin back with credentials allowed. Replace with an explicit allowlist.

⚠️ Enumerate the origins the mobile app uses before changing anything. REPLIT_DEV_DOMAIN and REPLIT_EXPO_DEV_DOMAIN exist for this. Get the list wrong and you break an app that's ready to ship and cannot be patched. Paste the allowlist and stop for approval before implementing.

3b. Session cookie signing. cookieParser() takes no secret, so rt_sid is an unsigned UUID.

⚠️ Signing invalidates every existing session — everyone gets logged out once. Harmless now, disruptive after launch. Confirm the timing before doing it.

3c. Security headers. Add helmet() or equivalent: X-Frame-Options, Content-Security-Policy, X-Content-Type-Options, Strict-Transport-Security. Replit's proxy supplies some on the dev domain; a custom domain gets none. Verify a CSP doesn't break the CRM or the portals before shipping it.

3d. GET /companies/:companyId. Unauthenticated, returns company name for any valid ID. Now P2 rather than P1 — 6 characters from a 31-character alphabet is ~887M, so enumeration isn't practical. Rate-limit it and leave it public, since it's the join-code confirmation flow.
