A3 — canvassing_heatmap  (manager+)  [REASONING OK]
═══════════════════════════════════════════════════════════
GOAL: where has the team been knocking, and what happened there.

DATA: pins.latitude / .longitude (both doublePrecision, NOT NULL) plus
doorKnockResult / contactOutcome for color-coding, createdAt for recency.

Leaflet is already set up in artifacts/rooftrax-web/src/pages/MapPage.tsx —
reuse that setup rather than introducing a second mapping approach.

Constraints:
  - Return only the columns the map needs. Do NOT return full pin rows with
    customer names, phone numbers, or addresses to a heatmap endpoint —
    that's PII on a surface that doesn't need it. Coordinates + outcome +
    timestamp is enough.
  - Cap the number of points returned and report the cap in the payload
    (same honesty rule as action_required: never silently truncate). A
    company with 50k pins must not blow up the response.
  - Consider a recency window (default to something sensible, say last 30
    or 90 days) rather than all-time. State what you chose.
  - Leaflet in a small dashboard card needs different interaction defaults
    than a full page — disable scroll-wheel zoom so the widget doesn't
    hijack page scrolling.

DATA: GET /location/team ALREADY EXISTS and returns exactly this — verified
