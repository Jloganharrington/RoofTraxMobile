STEP 4 — One metering implementation
claim_ledger (056) and pp_package_credits (059) are two meters. Under the two-stage model they measure different things — Stage 1 pays per package, Stage 2 pays per claim against a commitment — but the rule from §2.7 has to hold identically in both:

A claim is consumed when a proof package reaches delivered. Regeneration, revision, and supplement documents never re-consume.

Right now that rule has no shared implementation. Extract one consumption function that both surfaces call, keyed on package_id so re-delivery of the same package is idempotent rather than depending on status transitions.

Tests: deliver once consumes once; deliver the same package again consumes nothing; regenerate then re-deliver consumes nothing; a supplement on a delivered package consumes nothing; a genuinely new package on the same claim consumes once.
