║ STEP 1 [LOCKED] — OPENAPI RETROFIT                        ║
╚═══════════════════════════════════════════════════════════╝
⚠ The contracts endpoints are NOT in lib/api-spec/openapi.yaml — grep returns
zero matches. Both routes/contracts.ts and routes/contractPortal.ts were
built without spec entries, so no generated hooks exist, and
ContractBuilderTab.tsx calls them via customFetch with hand-written path
strings.

This is the exact pattern that caused two production incidents in this repo:
the legacy useGetMyProfile hitting a nonexistent /api/profile (broke Settings
AND LeadProfile silently), and a hand-written query key that didn't match the
generated one (left the financials waterfall stale after approving a change
order). It must not be allowed to set into the contract flow, which is the
most consequential surface in the app.

1a. Add ALL endpoints from routes/contracts.ts to openapi.yaml:
      GET/POST   /pins/{pinId}/contracts
      GET/PATCH  /contracts/{contractId}
      POST       /contracts/{contractId}/scope-packages
      PATCH/DELETE /contracts/{contractId}/scope-packages/{pkgId}
      POST       /contracts/{contractId}/send
      POST       /contracts/{contractId}/generate-document
      POST       /contracts/{contractId}/void
    Endpoint shapes stay EXACTLY as built — the spec documents reality, do
    not rename fields or paths.

1b. Add the public endpoints from routes/contractPortal.ts as well:
      GET  /portal/contract/{code}
      POST /portal/contract/{code}/select/{pkgId}
      GET  /portal/contract/{code}/document
      POST /portal/contract/{code}/generate-document
      POST /portal/contract/{code}/sign
    The signing-portal build needs these generated too.

1c. Regenerate the clients, then replace every customFetch call in
    ContractBuilderTab.tsx with the generated hooks. Use generated
    get*QueryKey functions for every queryKey AND every invalidateQueries —
    no literal array keys.
