FINANCIALS STEP 5 — PROJECT FINANCIALS RESTRUCTURE

Converts the lead P&L from a CASH basis (collected − costs) to an ACCRUAL
basis (revised contract − COGS − overhead). This is a redefinition, not a
rename — read the whole order before starting.

Money is integer cents everywhere. Standing rules: openapi-first then
regenerate; never hand-edit generated client files; never touch
artifacts/mobile/; server enforcement is authoritative.

STOP AT EACH CHECKPOINT and paste the listed output. Do not run steps
together — step 2's view depends on step 1's schema.

TARGET MODEL — the waterfall being built
═══════════════════════════════════════════════════════════
    Contract Value                    $15,000
    Change Orders (approved)          + $3,500
    ─────────────────────────────────────────
    Revised Contract Value            $18,500
    Cost of Goods Sold                − $8,000   ← vendor_expenses total
    Job Overhead                      − $2,500   ← the modal's total
    ─────────────────────────────────────────
    Net Project Margin                  $8,000   (43.2%)

COGS  = direct job costs — the existing vendor_expenses table
        (materials / labor / subcontractor / equipment / other).
        The Cost of Goods Sold line MUST equal the Expense Tracker total.
        Same source, no second aggregation.

JOB OVERHEAD = indirect project costs, all per-lead single values on pins:
        lead acquisition cost, referral fee, sales commission,
        canvassing commission, PM commission.

2a [LOCKED] CREATE OR REPLACE pin_profitability, adding:
    change_orders_cents
        SUM of change_orders WHERE status = 'approved' ONLY.
        Pending and rejected are excluded. COALESCE to 0.
    revised_contract_cents
        contract_amount (parsed via _parse_legacy_money_cents)
        + change_orders_cents
    net_project_margin_cents
        revised_contract_cents − total_cost_cents
    net_project_margin_pct
        revised_contract_cents > 0
          ? (net_project_margin_cents)::numeric / revised_contract_cents * 100
          : 0        ← guard, never NaN/Infinity/null

2b [LOCKED] total_cost_cents must now include canvassing commission.
Current definition sums vendor expenses + lead acquisition + referral +
sales + PM. Add canvassing. If any overhead line is missing from
total_cost_cents, Net Project Margin silently overstates profit.

2c [LOCKED] expected_total_cents must now use the REVISED contract:
    insurance → GREATEST(revised_contract_cents, approved_rcv_cents)
    retail    → revised_contract_cents
A change order that raises the contract must raise the projected baseline.
Keep cash_margin_pct exactly as-is — it is still collected-vs-costs and is
consumed by the company rollup later.

2d [LOCKED] Remove the legacy `marginPct` field from the profitability
response and its test. Nothing external consumes this API; a third margin
that can diverge from the other two is the exact drift this restructure
exists to eliminate.

Remember: pg returns numeric as STRING. The existing pct() coercion helper
in profitability.ts must cover every new percentage column.
