RoofTraxMobile — Phase M-B Work Order: Dashboard, Intake & Live Storm (S0–S1)
Depends on M-A being merged. Ships the first user-visible slice on both sides: the dashboard home, canvassing time tracking, and the front of the inspection flow through arrival and live storm verification.

Two standing constraints
Canvassing must keep working. One intended navigation change: the app home becomes the dashboard, and the map is now reached via "Add Pins." Every canvassing capability must remain functional through the new entry point; if pin behavior changes, stop and flag.
The app computes nothing derivable — stats/rankings are computed server-side and displayed.
Two CRM seams NOT built this phase
The CRM owns the appointment + inspection-schedule lifecycle and its multi-tenant rollout is in progress, so do not build the CRM integration in M-B:

Scheduled inspections (B3): the list reads a server source that returns only local walk-up inspections for now; the CRM-fed section stays empty behind a marked seam M-F wires.
Appointment "completed" (B1 panel): appointments set compute locally; completed is CRM-owned — expose the field, render a "pending"/— state, don't fabricate a local metric.
B1 — Dashboard home. Stats-first landing + department-gated buttons. Canvassing-only activity metrics (pins, appointments set, completed-stub, hours). field_rep sees own; manager+ get a total/department/individual toggle (enforced server-side). Competitive panel (trailing 30d): Me / Team total / My rank; rank-only for field_rep, named leaderboard for manager+. Server activity-stats endpoint computes aggregates + rank over the canvassing cohort.

B2 — Canvassing time tracking. New canvassing_sessions table; one open session per user; clock in/out on the Add Pins flow; hours surface on the dashboard. Additive — must not alter pin creation.

B3 — Inspections list + start-from-pin. Gated to inspector_canvasser + super_admin. List shows local inspections + an empty Scheduled section. "Start an Inspection" → drop-a-pin → create inspection anchored to that pin (status=capturing). Build the scheduled-record prefill path now; it has no data until M-F.

B4 — Claim intake + offline bundle. Intake form (insured, address, carrier, policy #, claim #, date of loss) prefilled from pin/scheduled record. Equipment attestation (S0) as an attestations row. Cache record + protocol checklists to SQLite; "ready for field" indicator.

B5 — Weather engine port + live storm verification. Port rooftrax-pro's deterministic storm retrieval (VisualCrossing) + rule-based gating into a tenant-scoped api-server endpoint (VISUALCROSSING_API_KEY). App calls it live in S0/S1, inspector confirms storm of record → stormConfirmedRef. Offline → queue + confirm on reconnect, soft gate. Do NOT port the AI hail-scoring — deferred pending the Opus-vs-Gemini model-consistency decision; no LLM dependency in M-B.

B6 — Arrival flow (S1). Address-verification + front-of-risk photos via the M-A evidence module; GPS-vs-geocode tolerance check (pass/fail/override-with-attestation); conditions log + personnel note; all offline-first.

Testing gate M-B: offline S0–S1 E2E with hash-matched sync; storm online + offline-retry soft-gate (no LLM in path); GPS-tolerance units; intake prefill + start-from-pin; per-role dashboard stats + rank against fixtures; standing pin regression through the new dashboard→Add Pins entry; typecheck. Evidence: test output + dashboard screenshots (field_rep and manager views).

Execution discipline: don't build the CRM integration; don't port AI hail-scoring; no bypass endpoints; diff reviewed against origin before pull; stop and report if forced outside the isolation boundary beyond the intended home→dashboard move.
