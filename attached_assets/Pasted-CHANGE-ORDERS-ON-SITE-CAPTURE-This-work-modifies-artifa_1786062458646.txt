MODEL
═══════════════════════════════════════════════════════════
A change order is a set of LINE ITEMS with a total, signed on site by the
homeowner. Two flavours, distinguished by one flag:
  required_to_complete_scope = true
      Hidden conditions / undocumented work discovered during the job that is
      necessary to complete the ORIGINAL scope (rotted decking found at
      tear-off). Document language reflects this. Supplement candidate on
      insurance jobs.
  required_to_complete_scope = false
      Homeowner-elected additional work / betterment.

BOTH count toward revised contract value once approved. The homeowner signs
either way and is responsible for payment either way — carrier reimbursement
is pursued separately and does not change the contract.

Builds on the change_orders table from the Project Financials step.

1a [LOCKED] New child table `change_order_line_items`:
    id                    varchar PK gen_random_uuid()
    company_id            varchar NOT NULL REFERENCES companies(id)
    change_order_id       varchar NOT NULL REFERENCES change_orders(id)
                            ON DELETE CASCADE
    description           text NOT NULL
    quantity              numeric NOT NULL DEFAULT 1
    unit_price_cents      integer NOT NULL     -- may be negative (credits)
    total_cents           integer NOT NULL     -- quantity × unit_price, stored
    price_book_item_id    varchar NULL REFERENCES price_book_items(id)
    sort_order            integer NOT NULL DEFAULT 0
    created_at / updated_at
Store total_cents rather than deriving it at read time — the signed document
must remain reproducible even if a price book item later changes.

1b [LOCKED] Extend `change_orders`:
    required_to_complete_scope  boolean NOT NULL DEFAULT false
    document_object_path        text NULL
    document_sha256             text NULL
    homeowner_signature_path    text NULL
    homeowner_signed_at         timestamptz NULL
    rep_signature_path          text NULL
    rep_signed_at               timestamptz NULL
    voided_at / voided_by_user_id / void_reason
Mirror signed_agreements' void semantics: a change order signed in error is
voided in place, never deleted, and a partial unique index permits a
replacement on the same pin.

change_orders.amount_cents becomes DERIVED — the sum of its line items. Do
not let it be set independently; recompute on line-item write. Two sources
of truth for the same number is how totals drift.

1c [LOCKED] Approval gate. status cannot transition to 'approved' unless
document_object_path AND homeowner_signed_at are both non-null. Enforce
server-side, not in the UI. This is what keeps an undocumented change order
out of revised contract value.

1d [LOCKED] Add 'change_order' to TEMPLATE_USE_CASES so the document language
is company-configurable through the Templates page already built.

1e [LOCKED] API, openapi-first:
    GET/POST    /pins/:pinId/change-orders          (create with line items)
    PATCH/DELETE /change-orders/:id
    POST        /change-orders/:id/sign             (document + signatures)
    POST        /change-orders/:id/approve          (manager+, gated by 1c)
    POST        /change-orders/:id/void             (manager+)
CREATE is allowed for field reps and PMs — they capture on site. APPROVE is
manager+. Separation of duties: the signature makes it real with the customer,
the approval makes it real in the money.
company_id/pin_id never client-settable on PATCH; whitelist mutable fields.
